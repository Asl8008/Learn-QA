Idempotentlikdan chiqadigan testlar

  • DELETE ni ikki marta yuboring — ikkinchisi xato bermasligi kerak.
  • PUT ni ikki marta yuboring — natija bir xil bo'lishi kerak.
  • POST ni ikki marta yuboring — dublikat yaratiladimi? Yaratilishi kerakmi? Bu savolni bering.

To'liq jadval: DevTools shpargalkasi.

Tipik API xatolari

  • Xato holati 200 bilan qaytariladi
  • Xato matni foydalanuvchiga tushunarsiz yoki texnik («NullPointerException»)
  • Xato matnida ortiqcha ma'lumot ochiladi (baza nomi, so'rov matni)
  • Validatsiya faqat interfeysda — server tekshirmaydi
  • Parol yoki token javobda ochiq qaytadi
  • Bo'sh ro'yxat o'rniga 500 qaytadi
  • Chegara qiymatlari qabul qilinmaydi (max = 100 bo'lsa-yu, 100 rad etilsa)

Faqat status kodiga qaramang

200 OK ichida {"error": …} turishi mumkin. Har doim status va body ni birga tekshiring.

Mashq uchun API lar

  • jsonplaceholder.typicode.com — ro'yxatdan o'tishsiz, o'qish uchun. Yozish so'rovlari haqiqatan saqlamaydi.
  • postman-echo.com — yuborgan so'rovingizni qaytarib ko'rsatadi, o'rganish uchun qulay.
  • api.restful-api.dev — haqiqiy CRUD: yaratganingiz saqlanadi.
