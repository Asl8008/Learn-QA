QA lug'ati

Bu hujjat o'sib boradi. Har bir darsdan keyin yangi atamalar qo'shiladi. Darslarda ishlatiladigan atamalar aynan shu ta'riflarga bo'ysunadi.

Xatoning uch bosqichi

Kundalik nutqda hammasi «xato» deyiladi, lekin QA da bu uch xil narsa. Farqni bilish muhim — chunki siz faqat uchinchisini ko'rasiz, ikkinchisini izlaysiz, birinchisini esa hech qachon ko'rmaysiz.

AtamaMa'nosiKim ko'radi
Error
(mistake, inson xatosi)		 Insonning noto'g'ri harakati. Dasturchi shartni teskari yozdi, analitik talabni noto'g'ri tushundi. Hech kim. Bu odamning boshida sodir bo'ladi.
Defect
(bug, nuqson)		 Shu xato natijasida kodda qolgan nuqson. Kodda o'tirib turadi, hatto hech kim uni ishga tushirmasa ham. Dasturchi — kodni o'qiganda.
Failure
(ishdan chiqish)		 Dastur ishga tushganda nuqson namoyon bo'lishi: noto'g'ri natija, qulash, xato xabar. Siz va foydalanuvchi — ekranda.

Eslab qoling

Error → Defect → Failure. Siz failure ni ko'rasiz va defect haqida hisobot yozasiz. Har bir defect failure ga olib kelavermaydi — ba'zi nuqsonlar shunchaki hech qachon ishga tushmaydi.

Manba: ISTQB CTFL Syllabus v4.0, 1.2.3-bo'lim.

Bug report atamalari

AtamaMa'nosi
Bug report
defect report		 Topilgan nuqson haqidagi hujjat. Maqsadi — dasturchi uni o'zi takrorlay olishi va tuzata olishi.
Steps to reproduce
takrorlash qadamlari		 Xatoni qaytadan chiqarish uchun bajariladigan aniq, raqamlangan harakatlar. Ma'lum boshlang'ich holatdan boshlanadi.
Expected result
kutilgan natija		 Dastur nima qilishi kerak edi. Talab, hujjat yoki sog'lom mantiqqa asoslanadi.
Actual result
haqiqiy natija		 Dastur aslida nima qildi. Faqat kuzatilgan fakt — taxmin emas.
Environment
muhit		 Qayerda sinaldi: brauzer va versiyasi, OS, qurilma, ilova build raqami. Ko'p xatolar faqat ma'lum muhitda chiqadi.
Reproducibility
takrorlanuvchanlik		 Xato har safar chiqadimi yoki ba'zan? Masalan «5 urinishdan 2 tasida». Har doim chiqmaydigan xato — flaky deyiladi.
Severity
jiddiylik		 Xato mahsulotga qanchalik texnik zarar yetkazadi. Buni tester belgilaydi.
Priority
muhimlik / navbat		 Uni qachon tuzatish kerak. Buni biznes (menejer, product owner) belgilaydi.

Klassik chalkashlik

Severity ≠ Priority. Kompaniya logotipi bosh sahifada noto'g'ri yozilgan bo'lsa — severity past (dastur ishlayapti), lekin priority juda yuqori (hamma ko'rib turibdi). Aksincha: yiliga bir marta ishlatiladigan hisobot sahifasi qulasa — severity yuqori, priority past.

Test dizayn atamalari

AtamaMa'nosi
Equivalence partition
ekvivalentlik sinfi		 Dastur bir xil ishlaydigan qiymatlar to'plami. Har bir sinfdan bitta qiymat sinalsa yetarli.
Boundary value
chegara qiymati		 Sinfning eng kichik yoki eng katta qiymati. Xatolar aynan shu yerda to'planadi.
2-value BVA Har bir chegara uchun ikkita qiymat: chegaraning o'zi va undan tashqaridagi qo'shni. Kundalik ishning standarti.
3-value BVA Yuqoridagiga ichkaridagi qo'shni ham qo'shiladi. Xato qimmatga tushadigan sohalarda (moliya, tibbiyot) ishlatiladi.
Black-box testing
qora quti		 Kodning ichiga qaramasdan, faqat kirish va chiqishga qarab testlash. Manual testerning asosiy usuli.
Precondition
dastlabki shart		 Test boshlangunicha tayyor bo'lishi kerak bo'lgan holat: hisob, ma'lumot, ochiq sahifa.
Checklist Bir qatorli tekshiruvlar ro'yxati — qisqartirilgan test case. Tez, lekin loyihani biladigan odam uchun.
Regression testing
regressiya		 Oldin ishlagan narsa hali ham ishlayaptimi — o'zgarishdan keyingi qayta tekshiruv.

Ikkita texnika, ikkita vazifa

Ekvivalentlik sinflari — hech bir holatni o'tkazib yubormaslik uchun (kenglik). Chegara qiymatlari — xato ehtimoli eng yuqori nuqtalarni urish uchun (aniqlik). Ular birga ishlatiladi.

Ikki xil qayta tekshiruv

Confirmation testing (retest) — o'sha xato tuzatildimi? Hisobotdagi qadamlar aynan qaytariladi. Regression testing — tuzatish boshqa narsani buzmadimi? Atrofdagi funksiyalar tekshiriladi.

Jarayon atamalari (Agile)

AtamaMa'nosi
User story Vazifaning foydalanuvchi tilidagi shakli: «[kim] sifatida men [nima] qilmoqchiman, chunki [nima uchun]».
Acceptance criteria
qabul qilish mezonlari		 Story tugaganini aniqlaydigan shartlar. Odatda Given/When/Then shaklida yoziladi.
Given / When / Then Boshlang'ich holat / harakat / natija. Test case'ning dastlabki shart, qadamlar va kutilgan natijasiga to'g'ri keladi.
Definition of Done
«tayyor» ta'rifi		 Barcha story'lar uchun umumiy shart: vazifa tayyor deyilishi uchun nima bajarilgan bo'lishi kerak.
Shift-left Sifat bilan bog'liq ishni jarayonning boshiga surish — tester kod yozilgunicha qatnashadi.
Sprint Qisqa ish davri (odatda 2 hafta), oxirida ishlaydigan mahsulot topshiriladi.
Backlog Bajarilishi kerak bo'lgan vazifalar ro'yxati, muhimlik bo'yicha tartiblangan.

Performance atamalari

AtamaMa'nosi

INP Bosgandan keyin ekran javob berish vaqti. Yaxshi natija — 200 ms gacha.
CLS Yuklanish paytida elementlarning siljishi. Yaxshi natija — 0.1 dan kichik.

Throttling Sekin tarmoq va kuchsiz protsessorni sun'iy yaratish (DevTools).
Lab va field o'lchov Nazorat qilinadigan sharoitdagi o'lchov (Lighthouse) va real foydalanuvchilardan yig'ilgan ma'lumot.

Stress testing Chegarada va undan tashqarida tizim qanday ishlashini tekshirish.
Spike testing To'satdan ko'tarilgan yukka javob berish va normal holatga qaytish.
Endurance testing Uzoq vaqt davomidagi barqarorlik — xotira sizishi, ulanishlar tugashi.
Xotira sizishi
memory leak		 Ishlatilgan xotira bo'shatilmasligi; vaqt o'tishi bilan tizim sekinlashadi yoki yiqiladi.

Playwright atamalari

Playwright Brauzerni dastur orqali boshqaradigan test asbobi. Testlar JavaScript, TypeScript, Python yoki C# da yoziladi.
Lokator
locator		 Sahifadagi elementni topish usuli. Test kodi sifatining asosiy ko'rsatkichi.
getByRole Elementni roli va nomi bo'yicha topish — tavsiya etilgan birinchi usul. Accessibility ma'lumotiga tayanadi.
Avtomatik kutish
auto-waiting		 Playwright element tayyor bo'lishini o'zi kutadi. Qo'lda sleep qo'shish shart emas va zararli.
Strict rejim Lokatorga bir nechta element mos kelsa, Playwright xato beradi — tasodifiy birini tanlamaydi.
await «Amal tugashini kut». Unutilishi beqaror testning eng ko'p uchraydigan sababi.
beforeEach Har bir testdan oldin bajariladigan qadamlar — test case'dagi «dastlabki shart» ning kod ko'rinishi.
codegen Harakatlarni yozib olib kodga aylantiradigan rejim. Faqat qoralama uchun — lokatorlarini qayta yozish kerak.

Avtomatlashtirish atamalari

AtamaMa'nosi
Test avtomatlashtirish Testlarni dastur orqali bajarish va natijani kutilgan qiymat bilan solishtirish. Yangi xato topmaydi — ma'lum tekshiruvni qayta-qayta bajaradi.

continuous integration		 Har bir kod o'zgarishida testlarni avtomatik yurgizadigan tizim.

interruption		 Ilova ishini to'xtatuvchi tashqi hodisa: qo'ng'iroq, bildirishnoma, ekran burilishi, fonga o'tish.

lifecycle		 Ilovaning yaratilish, to'xtatilish va yo'q qilinish bosqichlari. Ekran burilganda tizim ilovani yo'q qilib qaytadan quradi.

API atamalari

AtamaMa'nosi
API Interfeys bilan server orasidagi kelishuv. Uni to'g'ridan-to'g'ri sinash mumkin — interfeys tayyor bo'lmasa ham.
Endpoint API ning muayyan manzili: /api/users/42.
GET / POST / PUT / PATCH / DELETE O'qish / yaratish / to'liq almashtirish / qisman o'zgartirish / o'chirish.
Idempotent So'rovni bir marta ham, besh marta ham yuborsangiz natija bir xil. GET, PUT, DELETE — idempotent; POST — yo'q.
Xavfsiz metod
safe		 Server holatini o'zgartirmaydigan metod — faqat GET.
JSON Ma'lumot uzatish formati: {"id": 42, "phone": null}.
Header So'rov yoki javobga qo'shiladigan xizmat ma'lumoti: format, avtorizatsiya tokeni.
Body So'rov yoki javobning asosiy ma'lumot qismi.
Token Foydalanuvchi kimligini tasdiqlovchi kalit; odatda Authorization header'ida yuboriladi.
Postman So'rov yuborish va javobni ko'rish uchun dastur; so'rovlar collection ga saqlanadi.

Ma'lumotlar bazasi atamalari

AtamaMa'nosi
SQL Ma'lumotlar bazasiga so'rov yuborish tili. Testerga kerakli qismi — SELECT … FROM … WHERE ….
Jadval
table		 Bir turdagi yozuvlar to'plami: users, orders.
Ustun / qator
column / row		 Bitta xususiyat / bitta yozuv.
Primary key Qatorni yagona qilib ajratadigan ustun, odatda id.
Foreign key Boshqa jadvalga havola: orders.user_id → users.id.
NULL Qiymat yo'q. Nol ham, bo'sh matn ham emas — alohida holat. Faqat IS NULL orqali tekshiriladi.
JOIN Ikki jadvalni bog'lab birga o'qish.
COUNT / GROUP BY / HAVING Sanash, bir xil qiymatlarni guruhlash, guruhlarni filtrlash. Dublikat topishning asosiy usuli.

Test darajalari va turlari

AtamaMa'nosi
Test darajasi
test level		 Birgalikda tashkil etiladigan va boshqariladigan test faoliyatlari guruhi: component, integration, system, acceptance.
Component testing
unit test		 Alohida sinaladigan bitta qismni tekshirish. Odatda dasturchi yozadi.
Integration testing Qismlar yoki tizimlar orasidagi aloqani tekshirish.
System testing Butun mahsulotning xulqi va uchidan uchigacha oqimini tekshirish. Qo'lda ishlaydigan testerning asosiy maydoni.
Acceptance testing Mahsulot haqiqiy ehtiyojga mosligini tasdiqlash. Maqsad — xato topish emas, ishonch hosil qilish.
UAT / OAT Foydalanuvchi tomonidan qabul testi / administratorlar tomonidan (zaxira, o'rnatish, tiklash).
Alpha / Beta Ishlab chiquvchi muhitida tashqi odamlar bilan / haqiqiy foydalanuvchilarda o'z muhitida o'tkaziladigan test.
Funksional testing Tizim nima qilishini baholaydi.
Nofunksional testing Tizim qanchalik yaxshi ishlashini baholaydi: tezlik, qulaylik, xavfsizlik, moslik, ishonchlilik.
Oq quti testing
white-box		 Ichki tuzilish — kod, arxitektura, ma'lumot oqimi — asosida test tuzish.
Qamrov
coverage		 Testlar qancha element (talab, kod, qurilma) ni qamrab olgani, foizda.
ISO/IEC 25010 Dasturiy mahsulot sifati xususiyatlarining xalqaro modeli — nofunksional turlar shundan olinadi.

Mahsulot riski

Loyiha riski

Smoke test Qisqa yuzaki tekshiruv: asosiy yo'l umuman ishlayaptimi? Chuqur testdan oldin o'tkaziladi.

Bug tracker atamalari (Jira)

AtamaMa'nosi
Bug tracker Xatolar va vazifalar yuritiladigan tizim. Eng tarqalgani — Jira; shuningdek Azure DevOps, YouTrack, Redmine, GitHub Issues.
Issue
work item		 Trackerdagi bitta karta: bitta xato, vazifa yoki story. O'z raqami bo'ladi (SWAG-42).
Workflow Issue yaratilishdan yopilishgacha bosib o'tadigan yo'l.
Status Issue workflow ichida hozir qayerda turgani: To Do, In Progress, In Test, Done.
Transition Issue'ni bir statusdan boshqasiga o'tkazadigan harakat.
Resolution Issue qanday tugagani: Done, Won't do, Duplicate, Cannot Reproduce. Statusdan farq qiladi.
Assignee Issue ustida hozir kim ishlayotgani.
Reporter Issue'ni kim yaratgani — bug bo'lsa, odatda tester.
Component Mahsulotning qismi: «Savat», «Avtorizatsiya», «To'lov».
Affects / Fix version Xato topilgan versiya va tuzatilgan versiya.
Epic Ko'plab story'ni birlashtiruvchi katta yo'nalish.
JQL
Jira Query Language		 Jira'dagi qidiruv tili: type = Bug AND status = "In Test".

Umumiy atamalar

AtamaMa'nosi
QA
