CI shpargalkasi

Testlarni jarayonga ulaganda va qizil build'ni tahlil qilganda shu sahifani oching.

Tushunchalar

AtamaMa'nosi
WorkflowAvtomatik jarayon: qachon, qayerda, nima bajarilishi
EventWorkflow'ni ishga tushiradigan hodisa (push, pull request, jadval)
JobBitta serverda bajariladigan qadamlar to'plami
StepBitta buyruq yoki tayyor action
ActionQayta ishlatiladigan tayyor qism
RunnerWorkflow ishlaydigan server
ArtifactIsh natijasida saqlanadigan fayl: hisobot, skrinshot, video, trace

Tayyor workflow (Playwright)

name: Playwright Tests
on:
  push:
    branches: [ main, master ]
  pull_request:
    branches: [ main, master ]
jobs:
  test:
    timeout-minutes: 60
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v6
    - uses: actions/setup-node@v6
      with:
        node-version: lts/*
    - name: Install dependencies
      run: npm ci
    - name: Install Playwright Browsers
      run: npx playwright install --with-deps
    - name: Run Playwright tests
      run: npx playwright test
    - uses: actions/upload-artifact@v4
      if: ${{ !cancelled() }}
      with:
        name: playwright-report
        path: playwright-report/
        retention-days: 30

Fayl joyi: .github/workflows/playwright.yml

Manba: Playwright Docs — Setting up CI.

Qaysi testlar qachon

QachonNimaVaqt chegarasi
Har commitUnit + API + smoke UI 5–10 daqiqa
Pull request+ asosiy UI oqimlari 15–20 daqiqa
KechasiTo'liq to'plam, bir necha brauzer Cheklanmagan
Reliz oldidanTo'liq regression + exploratory Reja bo'yicha

10 daqiqa qoidasi

Har commit'da yuradigan to'plam 10 daqiqadan uzun bo'lsa, dasturchilar natijani kutmay qo'yadi va CI ma'nosini yo'qotadi. Tez to'plamni qisqa ushlab turish — testerning doimiy vazifasi.

Qizil build'ni tahlil qilish

  1. Qaysi qadamda to'xtadi — o'rnatishda yoki testda?
  2. Xato xabarini o'qing: nima kutilgan, nima topilgan?
  3. Artifact'ni yuklab oling (hisobot, skrinshot, video, trace)
  4. npx playwright show-report bilan oching
  5. Tasnif qiling: haqiqiy bug / test xatosi / muhit muammosi
TasnifHarakat
Haqiqiy bugBug report yozing (1-dars), testni o'zgartirmang
Test xatosiLokator yoki kutilgan natijani tuzating
Muhit muammosiSozlamani tuzating; takrorlansa, alohida vazifa qiling
Beqaror (flaky)Tuzating yoki o'chiring — oraliq yo'q

Tuzoqlar

  • Test mahalliy ma'lumotga bog'lanmasin — CI da toza server bo'ladi
  • Parol va token kodda yozilmasin — Secrets ishlating
  • node_modules .gitignore da bo'lsin
  • Testlar bir-biriga va bajarilish tartibiga bog'liq bo'lmasin
  • Hisobot artifact sifatida saqlansin — yiqilganda ham
  • Qizil build darhol tuzatilsin: yashil normal, qizil hodisa

Repozitoriyga tushgan parol

Uni o'chirib tashlash yetmaydi — u git tarixida qoladi. Shuning uchun umuman yozmaslik kerak. Agar tushib qolgan bo'lsa: parolni almashtiring, faqat o'chirish bilan cheklanmang.

Repozitoriy havolangizni yuboring. Workflow faylingizni va qizil build'ni tahlil qilish tajribangizni ko'rib chiqaman.
