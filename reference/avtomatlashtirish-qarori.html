Avtomatlashtirish qarori

«Buni avtomatlashtiraymi?» degan savol tug'ilganda shu sahifani oching. Qaror kod yozishdan oldin qabul qilinadi.

Oddiy hisob

Qo'lda
bir marta bajarish vaqti × yiliga necha marta
Avtomat

Qaror
Ikkinchisi birinchisidan kichik bo'lsa — avtomatlashtiring. Bunga risk va barqarorlikni ham qo'shing.

Amaliy qoida

Avtomatlashtirmoqchi bo'lgan har bir testni so'rang: «buni API darajasida qilib bo'ladimi?» Ha bo'lsa — pastga tushiring. Faqat foydalanuvchi yo'lini uchidan uchigacha tekshirish kerak bo'lgandagina UI darajasida qoldiring.

Nima avtomatlashtirilmaydi

  • Exploratory sessiyalar
  • Qulaylik va dizayn bahosi
  • Bir marta bajariladigan tekshiruv
  • Hali o'zgarib turgan yangi ekran
  • Natijasi «chiroyli/qulay» kabi so'zlar bilan o'lchanadigan test

Flaky test qoidasi

Goh o'tadigan, goh yiqiladigan testni tuzating yoki o'chiring. Uchinchi yo'l yo'q. Beqaror test butun to'plamga bo'lgan ishonchni yo'q qiladi va haqiqiy xatolarni yashiradi.

O'rganish tartibi

  1. Bitta til: Python yoki JavaScript (asoslari yetadi)
  2. API avtomatlashtirish — eng arzon boshlanish
  3. UI avtomatlashtirish: Playwright yoki Selenium
  4. CI — testlarni har o'zgarishda avtomatik yurgizish

Manbalar: ISTQB CTFL — Tool Support for Testing, Martin Fowler — TestPyramid.

Qarorlaringizni yuboring. Ayniqsa «avtomatlashtirilmaydi» deb belgilaganlaringizni — yangi boshlovchilar odatda juda ko'p narsani avtomatlashtirishga urinadi.
