Performance shpargalkasi

«Sekin» degan so'zni raqamga aylantirish uchun. O'lchash tartibi, chegaralar va hisobot shabloni.

Core Web Vitals

Ko'rsatkichNimaYaxshi
LCP Eng katta mazmun bloki qachon ko'rinadi ≤ 2.5 s
INP Bosgandan keyin ekran qachon javob beradi ≤ 200 ms
CLS Yuklanishda elementlar qancha siljiydi < 0.1

O'lchov 75-protsentil bo'yicha, mobil va desktop alohida. O'rtacha qiymat eng yomon holatlarni yashiradi.

Manba: web.dev — Web Vitals.

O'lchash tartibi

  1. DevTools → Lighthouse → Performance — umumiy manzara
  2. Network → throttling: Slow 4G; CPU 4–6× sekinlashtirish
  3. Network panelini hajm bo'yicha saralash — eng og'ir fayl
  4. Network panelini vaqt bo'yicha saralash — eng sekin so'rov
  5. So'rovlar sonini ko'rish
  6. Qayta yuklash — kesh ishlayaptimi
  7. Ma'lumot hajmini oshirish — 3 ta emas, 500 ta element bilan
  8. Kamida uch marta o'lchash

Ikki xil o'lchov

Lab — nazorat qilinadigan sharoitda, sizning mashinangizda (Lighthouse). Field — real foydalanuvchilardan yig'ilgan. Ikkisi bir xil bo'lmaydi; ikkalasi ham kerak.

Ta'riflar: ISTQB CTFL — Performance Testing syllabus.

⚠ Yuk testi — ruxsat bilan

Ishlab turgan real tizimda (production) o'z bilganingiz bilan o'tkazmang; begona tizimda umuman o'tkazmang. Alohida test muhiti, kelishilgan vaqt va yozma ruxsat kerak.

Performance mezoni: to'rt element

Ko'rsatkich
LCP, INP, CLS yoki javob vaqti
Chegara
Aniq raqam va protsentil: «75-protsentilda ≤ 3 s»
Sharoit
Tarmoq (Slow 4G) va qurilma (o'rta darajali telefon)
Ma'lumot hajmi
«500 ta mahsulot bilan», «1000 ta yozuvli ro'yxatda»

To'rttasidan biri yo'q bo'lsa — mezon tekshirib bo'lmaydigan bo'lib qoladi.

Performance bug report

  • Sarlavhada raqam bor
  • Throttling sozlamalari yozilgan
  • Ma'lumot hajmi ko'rsatilgan
  • Kamida uch o'lchov natijasi keltirilgan
  • Talab qiymati bilan solishtirilgan
  • Network panelidagi eng sekin so'rov ko'rsatilgan
  • Skrinshot yoki HAR fayli ilova qilingan
