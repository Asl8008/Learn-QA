# QA Testing manbalari

Darslardagi har bir da'vo shu ro'yxatdagi manbalarga tayanadi. O'z xotiramdan
"shunday bo'lsa kerak" deb yozilmaydi.

## Bilim (Knowledge)

- [ISTQB Certified Tester Foundation Level Syllabus v4.0.1 (bepul PDF)](https://istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf)
  Sohaning xalqaro standart darsligi — atamalar, test darajalari, test dizayn
  texnikalari, defect management. **Qachon kerak:** rasmiy ta'rif yoki atama
  kerak bo'lganda. 5.5-bo'lim — defect (xato) boshqaruvi. Til: ingliz.

- [ISTQB Glossary](https://glossary.istqb.org/)
  Atamalarning rasmiy lug'ati. **Qachon kerak:** "bu atama aynan nimani anglatadi?"
  degan savol tug'ilganda. Bizning [reference/lugat.html](./reference/lugat.html)
  shu manbaga tayanadi.

- [BrowserStack — How to write an Effective Bug Report](https://www.browserstack.com/guide/how-to-write-a-bug-report)
  Bug report tuzilishi bo'yicha amaliy va tekshirilgan qo'llanma.
  **Qachon kerak:** bug report yozish, misollar ko'rish.

- [QA Wolf — What makes a great bug report](https://www.qawolf.com/blog/what-makes-a-great-bug-report)
  Dasturchi nuqtai nazaridan: qaysi bug report ish qilishga yaraydi, qaysi biri yo'q.
  **Qachon kerak:** bug report sifatini oshirish.

- [ISTQB Syllabus 4.2 — Black-Box Test Techniques](https://astqb.org/4-2-black-box-test-techniques/)
  Ekvivalentlik sinflari, chegara qiymatlari, qaror jadvali, holat o'tishlari —
  rasmiy ta'riflar bilan. **Qachon kerak:** «nimani sinayman?» degan savolga
  tizimli javob kerak bo'lganda. 2-darsning asosi.

- [ISTQB — Boundary Value Analysis (rasmiy white paper, 2025)](https://istqb.org/wp-content/uploads/2025/10/Boundary-Value-Analysis-white-paper.pdf)
  Faqat chegara qiymatlariga bag'ishlangan rasmiy hujjat: 2-value va 3-value
  usullari batafsil. **Qachon kerak:** chegara tahlilini chuqurroq o'rganish.

- [TestRail — How to Write Effective Test Cases](https://www.testrail.com/blog/effective-test-cases-templates/)
  Test case tuzilishi va shablonlari. TestRail — sohada eng ko'p ishlatiladigan
  test boshqaruv vositalaridan biri. **Qachon kerak:** test case yozish. 3-darsning asosi.

- [Qase — How to Write Test Cases](https://www.qase.io/blog/how-to-write-test-cases/)
  Yuqoridagiga qo'shimcha nuqtai nazar, ko'proq amaliy misollar bilan.
  **Qachon kerak:** test case yozishda ikkinchi fikr kerak bo'lganda.

- [ISTQB Syllabus 5.5 — Defect Management](https://astqb.org/5-5-defect-management/)
  Nuqsonlarni boshqarish jarayoni: hisobot yo'li, holatlar, klassifikatsiya.
  **Qachon kerak:** bug hayot sikli. 4-darsning asosi.

- [Guru99 — Defect Life Cycle](https://www.guru99.com/defect-life-cycle.html)
  Bug holatlari diagrammalar bilan, amaliy va batafsil. **Qachon kerak:**
  holatlar oqimini ko'z bilan ko'rish.

- [James Bach — Exploratory Testing Explained (PDF)](https://satisfice.us/articles/et-article.pdf)
  Sohaning asoschisi yozgan asosiy maqola. **Qachon kerak:** exploratory
  testing nima va nega ishlaydi. 5-darsning asosi.

- [Session-based testing — Wikipedia](https://en.wikipedia.org/wiki/Session-based_testing)
  Charter, timebox, debrief tushunchalarining kelib chiqishi va ta'riflari.
  **Qachon kerak:** sessiya tuzilishini tushunish.

- [Chrome for Developers — DevTools](https://developer.chrome.com/docs/devtools/)
  Google ning rasmiy hujjati. Ayniqsa
  [Network activity](https://developer.chrome.com/docs/devtools/network/) va
  [Keyboard shortcuts](https://developer.chrome.com/docs/devtools/shortcuts)
  bo'limlari. **Qachon kerak:** DevTools bilan ishlash. 6-darsning asosi.

- [Kitob: _Explore It!_ — Elisabeth Hendrickson (Pragmatic Bookshelf)](https://pragprog.com/titles/ehxta/explore-it/)
  Exploratory testing bo'yicha eng kuchli amaliy kitob. Ilovasidagi
  "Test Heuristics Cheat Sheet" — testerlar orasida afsonaviy hujjat.
  **Qachon kerak:** "nimani test qilay?" degan savolga javob kerak bo'lganda.

- [Test Heuristics Cheat Sheet — Hendrickson, Lyndsay, Emery](https://blog.tentamen.eu/testing-heuristics-cheat-sheet/)
  Yuqoridagi kitobning 2 betlik siqilgan varianti — qaysi joylarni sindirishga
  urinish kerakligi ro'yxati. **Qachon kerak:** amaliy test sessiyasi oldidan.

- [ISTQB — Certified Tester AI Testing (CT-AI)](https://istqb.org/certifications/certified-tester-ai-testing-ct-ai/)
  AI va testing kesishmasi bo'yicha rasmiy sertifikat dasturi; sillabus
  bepul. **Qachon kerak:** AI asboblaridan foydalanish. 24-darsning asosi.

- [W3C — Authoring HTML: Internationalization techniques](https://www.w3.org/International/techniques/authoring-html)
  UTF-8, til e'loni, matn yo'nalishi va kengayishi bo'yicha rasmiy
  tavsiyalar. **Qachon kerak:** lokalizatsiya testi. 22-darsning asosi.

- [Uzbek alphabet — Wikipedia](https://en.wikipedia.org/wiki/Uzbek_alphabet)
  Oʻ va Gʻ uchun rasmiy Unicode belgisi (`U+02BB`) va amalda ishlatiladigan
  variantlar. **Qachon kerak:** apostrof bilan bog'liq buglarni
  hujjatlashtirishda. Bu — o'zbek tili bo'yicha topilgan yagona aniq
  texnik manba; QA bo'yicha o'zbekcha manba hali yo'q.

- [Playwright Docs — Setting up CI](https://playwright.dev/docs/ci-intro)
  Tayyor GitHub Actions workflow fayli va uni sozlash.
  **Qachon kerak:** testlarni jarayonga ulash. 20-darsning asosi.

- [GitHub Docs — Understanding GitHub Actions](https://docs.github.com/en/actions/get-started/understanding-github-actions)
  Workflow, event, job, step, action va runner ta'riflari.
  **Qachon kerak:** CI faylini o'qish va o'zgartirish.

- [Playwright Docs — Writing tests](https://playwright.dev/docs/writing-tests)
  Birinchi test, harakatlar va tekshiruvlar. **Qachon kerak:** kod yozishni
  boshlaganda. 19-darsning asosi. Lokatorlar bo'yicha alohida:
  [Locators](https://playwright.dev/docs/locators) — bu sahifaga bir necha
  marta qaytasiz.

- [web.dev — Web Vitals](https://web.dev/articles/vitals)
  LCP, INP, CLS ta'riflari, chegara qiymatlari va 75-protsentil qoidasi.
  **Qachon kerak:** tezlikni o'lchash. 18-darsning asosi.

- [ISTQB CTFL — Performance Testing syllabus (PDF)](https://astqb.org/assets/documents/ISTQB-CTFL-PT-Syllabus-2018.pdf)
  Load, stress, spike, endurance, scalability, concurrency va capacity
  testlarining rasmiy ta'riflari. **Qachon kerak:** yuk testi turlarini
  ajratish.

- [W3C WAI — Easy Checks](https://www.w3.org/WAI/test-evaluate/preliminary/)
  Mutaxassis bo'lmaganlar uchun to'qqizta accessibility tekshiruvi, har
  biri batafsil qadamlar bilan. **Qachon kerak:** accessibility sessiyasi.
  17-darsning asosi. Tamoyillar:
  [Accessibility Principles](https://www.w3.org/WAI/fundamentals/accessibility-principles/).
  To'liq mezonlar: [WCAG 2.2 Quick Reference](https://www.w3.org/WAI/WCAG22/quickref/).

- [OWASP Top 10:2025](https://owasp.org/Top10/2025/)
  Veb-ilovalar uchun eng jiddiy xavflar ro'yxati — sohaning umumiy tili.
  **Qachon kerak:** xavfsizlik tekshiruvlari. 16-darsning asosi.
  Chuqurroq: [OWASP Web Security Testing Guide](https://owasp.org/www-project-web-security-testing-guide/).

- [Martin Fowler — TestPyramid](https://martinfowler.com/bliki/TestPyramid.html)
  Nima uchun interfeys orqali avtomatlashtirish mo'rt va qimmat; qaysi
  qatlamda qancha test bo'lishi kerak. Sohaning asosiy matnlaridan biri.
  **Qachon kerak:** avtomatlashtirish rejasini tuzishda. 14-darsning asosi.

- [ISTQB CTFL Syllabus — Tool Support for Testing](https://astqb.org/6-1-tool-support-for-testing/)
  Avtomatlashtirishning foydalari va xavflari, yondashuvlar (record,
  data-driven, keyword-driven). **Qachon kerak:** «avtomatlashtiraymi?»
  degan qarorni asoslashda.

- [Android Developers — The activity lifecycle](https://developer.android.com/guide/components/activities/activity-lifecycle)
  Ilova qanday yaratiladi, to'xtatiladi va yo'q qilinadi. Ekran burilganda
  ma'lumot nima uchun yo'qolishi shu yerda tushuntirilgan.
  **Qachon kerak:** mobil testing. 13-darsning asosi.

- [Android Developers — Permissions on Android](https://developer.android.com/guide/topics/permissions/overview)
  Runtime ruxsatlar modeli va rad etilganda ilova qanday ishlashi kerakligi.
  **Qachon kerak:** ruxsat bilan bog'liq testlarni loyihalashda.

- [MDN — HTTP request methods](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Methods)
  GET/POST/PUT/PATCH/DELETE ta'riflari, xavfsizlik va idempotentlik jadvali.
  **Qachon kerak:** API test qilish. 12-darsning asosi.

- [Postman Docs — sending the first request](https://learning.postman.com/docs/getting-started/first-steps/sending-the-first-request)
  Postman bilan birinchi so'rovni yuborish. **Qachon kerak:** dasturni
  o'rnatib, ishni boshlaganda.

- [PostgreSQL Documentation — Querying a Table](https://www.postgresql.org/docs/current/tutorial-select.html)
  `SELECT`, `WHERE`, `ORDER BY`, `DISTINCT` ning rasmiy va qisqa tushuntirishi.
  **Qachon kerak:** bazani tekshirish. 11-darsning asosi.

- [ISTQB CTFL Syllabus — Test Levels and Test Types](https://astqb.org/2-2-test-levels-and-test-types/)
  Component / integration / system / acceptance darajalari va funksional,
  nofunksional, oq quti, o'zgarishga bog'liq turlar.
  **Qachon kerak:** «mening ishim qayerda boshlanadi?» savoliga javob.
  10-darsning asosi.

- [ISTQB CTFL Syllabus — 5.1 Test Planning](https://astqb.org/5-1-test-planning/)
  Test plan, kirish/chiqish mezonlari, vaqt bahosi va prioritetlash.
  **Qachon kerak:** reja tuzayotganda. 9-darsning asosi.

- [ISTQB CTFL Syllabus — 5.2 Risk Management](https://astqb.org/5-2-risk-management/)
  Risk, ehtimollik, ta'sir va risk-based testing ta'riflari.
  **Qachon kerak:** «nimadan boshlayman?» degan savolga javob kerak bo'lganda.

- [Introduction to Jira Workflows — Atlassian](https://www.atlassian.com/software/jira/guides/workflows/overview)
  Status, transition va resolution tushunchalarining rasmiy ta'riflari.
  **Qachon kerak:** bug tracker mantiqini tushunish. 8-darsning asosi.

- [Statuses, priorities and resolutions — Atlassian Support](https://support.atlassian.com/jira-cloud-administration/docs/what-are-issue-statuses-priorities-and-resolutions/)
  Standart prioritet shkalasi (Highest…Lowest) va resolution ro'yxati.
  **Qachon kerak:** bug ga prioritet qo'yayotganda.

- [Advanced search with JQL — Atlassian Support](https://support.atlassian.com/jira-software-cloud/docs/use-advanced-search-with-jira-query-language-jql/)
  Jira qidiruv tili. **Qachon kerak:** loyihada issue'lar ko'payib ketganda.

## Amaliyot maydonlari (mashq qilish uchun saytlar)

- [Swag Labs — saucedemo.com](https://www.saucedemo.com/)
  Sauce Labs tomonidan testerlar mashq qilishi uchun qurilgan demo do'kon.
  Ba'zi foydalanuvchi hisoblari **atayin buzuq** — real xatolar topiladi.
  **Qachon kerak:** bug topish va bug report yozish mashqi.

- [The Internet — Elemental Selenium](https://the-internet.herokuapp.com/)
  Veb-ilovalarning qiyin holatlari to'plami (dinamik yuklash, fayl yuklash,
  alertlar). **Qachon kerak:** turli xil UI holatlarini test qilishni o'rganish.

- [jsonplaceholder.typicode.com](https://jsonplaceholder.typicode.com/)
  Bepul test API — ro'yxatdan o'tish kerak emas. Yozish so'rovlari
  ma'lumotni haqiqatan saqlamaydi (shunday mo'ljallangan).
  **Qachon kerak:** 12-dars amaliyoti. Haqiqiy CRUD kerak bo'lsa —
  [api.restful-api.dev](https://api.restful-api.dev/objects).

- [SQLBolt](https://sqlbolt.com/)
  Brauzerda ishlaydigan interaktiv SQL darslari. Ro'yxatdan o'tish va
  o'rnatish kerak emas; har bir mashq darhol tekshiriladi.
  **Qachon kerak:** 11-dars amaliyoti (1–6-darslar yetarli).

- [Jira Cloud — bepul reja](https://www.atlassian.com/software/jira/free)
  10 foydalanuvchigacha bepul. **Qachon kerak:** o'z test loyihangizni yuritish
  va portfolio to'plash (8-dars amaliyoti).

## Donolik (Wisdom) — hamjamiyatlar

- [Ministry of Testing](https://www.ministryoftesting.com/)
  Dunyodagi eng nufuzli tester hamjamiyati — forum (The Club), maqolalar, tadbirlar.
  **Qachon kerak:** o'z ishingizni tajribali testerlarga ko'rsatib, fikr olish.

- [r/QualityAssurance](https://www.reddit.com/r/QualityAssurance/)
  Amaliyotchi testerlar subredditi — karyera savollari, real ish holatlari.
  **Qachon kerak:** "bu sohada aslida qanday ishlashadi?" degan savollarga javob.

- [Ministry of Testing — Portfolio](https://www.ministryoftesting.com/software-testing-glossary/portfolio)
  Portfolio nima, nimalardan iborat va karyerada qanday yordam beradi.
  **Qachon kerak:** ish qidirishga tayyorlanish. 15-darsning asosi.

- [ASTQB — Foundation Level](https://astqb.org/certifications/foundation-level/)
  ISTQB CTFL imtihoni haqidagi rasmiy faktlar: 40 savol, 60 daqiqa, 65 %.
  **Qachon kerak:** sertifikat olish haqida qaror qabul qilishda.

> Foydalanuvchi hamjamiyatga qo'shilish bo'yicha hali fikr bildirmagan.
> 15-darsda taklif qilindi.

## Bo'shliqlar (Gaps)

- **O'zbek tilidagi ishonchli QA manbalari topilmagan.** Hozircha barcha birlamchi
  manbalar ingliz tilida; men ularni o'zbekchaga tarjima qilib, darslarga
  singdiraman. Agar foydalanuvchi ingliz tilini yaxshi bilsa, to'g'ridan-to'g'ri
  manbaga yo'naltirish samaraliroq bo'ladi — buni aniqlash kerak.
- ~~Mobil ilovalarni test qilish bo'yicha manba hali tanlanmagan.~~ Yopildi
  (13-dars): Android rasmiy hujjatlari — activity lifecycle va permissions.
  iOS tomonidan ekvivalent manba hali qo'shilmagan.
- Test case boshqaruvi vositalari (TestRail, Jira, Zephyr) bo'yicha manba yo'q —
  amaliy darsga yetganda qo'shiladi.
