Ekran aldashi mumkin: SQL

Interfeys «Buyurtma qabul qilindi» deb yozadi. Lekin bazada nima saqlandi? Bu darsdan keyin siz buni o'zingiz tekshira olasiz — va bug report'laringiz butunlay boshqa darajaga chiqadi.

Nima uchun testerga SQL kerak

Real holat

Foydalanuvchi ro'yxatdan o'tdi. Ekranda «Muvaffaqiyatli» yozuvi chiqdi. Hammasi yaxshi ko'rinadi.

Bazaga qarasangiz: ism maydonida "Asilbek " — oxirida ortiqcha bo'sh joy bilan. Ertaga bu foydalanuvchi qidiruvda topilmaydi, chekda ismi g'alati chiqadi, eksportda ustun siljiydi. Xato bugun tug'ildi, lekin uch oydan keyin «tushunarsiz» muammo sifatida qaytadi.

Interfeys — mahsulotning faqat bir qatlami. Ma'lumot esa bazada yashaydi, va u yerda ko'p narsa noto'g'ri bo'lishi mumkin: bo'sh joylar, dublikatlar, NULL qiymatlar, noto'g'ri status, kesilgan matn.

Ikki foyda

1. Kuchli hisobot. «Ekranda buyurtma "Yetkazildi" deb ko'rinadi, lekin orders jadvalidagi status pending» — bunday hisobotni hech kim qaytarib yubormaydi.

2. Ish e'lonlari. «SQL asoslari» deyarli har bir QA vakansiyasida turadi. Bu — kod yozishni bilmasdan o'rganish mumkin bo'lgan eng foydali texnik ko'nikma.

Baza qanday tuzilgan

Ma'lumotlar bazasi — jadvallar to'plami. Har bir jadval Excel varag'iga o'xshaydi:

AtamaMa'nosi
Jadval table Bir turdagi ma'lumotlar to'plami: users, orders
Ustun column Bitta xususiyat: email, created_at
Qator row Bitta yozuv: bitta foydalanuvchi, bitta buyurtma
Primary key Qatorni yagona qilib ajratadigan ustun, odatda id
Foreign key Boshqa jadvalga havola: orders.user_id → users.id
NULL Qiymat yo'q. Bu nol ham, bo'sh matn ham emas — alohida holat

NULL — testerning do'sti

NULL, 0 va '' (bo'sh matn) — uchta boshqa-boshqa narsa. Ko'p xato aynan shu farqdan tug'iladi: kod NULL ni kutmaganda sahifa oq bo'lib qoladi. 2-darsdagi «unutilgan sinflar» ro'yxatiga NULL ni ham qo'shing.

Bitta so'rov — ishning 90 %

Testerga kerakli SQL ning asosi bitta jumla:

SELECT ustunlar
FROM jadval
WHERE shart;
So'rovni «cheklash» mumkin — buning uchun qaysi qatorlar kerakligini belgilaydigan WHERE qismi qo'shiladi. PostgreSQL Documentation — Querying a Table

Amaliy misollar:

-- Barcha ustunlarni ko'rish
SELECT * FROM users;

-- Faqat kerakli ustunlar
SELECT id, email, created_at FROM users;

-- O'zimning test yozuvimni topish
SELECT * FROM users WHERE email = 'test01@mail.uz';

-- Eng oxirgi 10 ta buyurtma
SELECT * FROM orders ORDER BY created_at DESC LIMIT 10;

* — «barcha ustunlar» degan qisqartma. ORDER BY natijani tartiblaydi (DESC — teskari tartib), LIMIT — nechta qator qaytarishni cheklaydi.

Eng ko'p qilinadigan xato

WHERE phone = NULL hech qachon ishlamaydi — natija har doim bo'sh bo'ladi. To'g'risi: WHERE phone IS NULL. Sababi: NULL «noma'lum» degani, noma'lum narsa esa hech narsaga, hatto o'ziga ham teng emas.

Testerning beshta doimiy so'rovi

-- 1. Mening test yozuvim saqlandimi?
SELECT * FROM users WHERE email = 'test01@mail.uz';

-- 2. Dublikat bormi? (1 dan katta son chiqsa — bug)
SELECT email, COUNT(*) FROM users
GROUP BY email HAVING COUNT(*) > 1;

-- 3. Majburiy maydon bo'sh qolganmi?
SELECT * FROM orders WHERE user_id IS NULL;

-- 4. Nechta yozuv bor?
SELECT COUNT(*) FROM orders WHERE status = 'pending';

-- 5. Oxirgi yaratilgan yozuvni ko'rish
SELECT * FROM orders ORDER BY id DESC LIMIT 1;

COUNT(*) — qatorlar sonini sanaydi. GROUP BY bir xil qiymatlarni guruhlaydi, HAVING esa guruhlarni filtrlaydi — ikkinchi so'rov aynan shu tarzda dublikatlarni topadi.

Ikki jadvalni birlashtirish: JOIN

Buyurtma orders jadvalida, foydalanuvchi users jadvalida. Ikkalasini birga ko'rish uchun:

SELECT orders.id, orders.total, users.email
FROM orders
JOIN users ON orders.user_id = users.id
WHERE orders.status = 'pending';

ON qismi ikki jadval qanday bog'langanini aytadi — bu deyarli har doim foreign key. Hozircha shu bitta shakl yetadi.

⚠ Xavfsizlik qoidasi — buni yodlang

Tester bazada faqat o'qiydi. UPDATE, DELETE, DROP buyruqlarini umumiy bazada ishlatmang.

DELETE FROM users; — bitta unutilgan WHERE butun jadvalni o'chiradi va orqaga qaytarib bo'lmaydi. Agar o'zgartirish kerak bo'lsa: avval SELECT bilan qaysi qatorlarga tegishini ko'ring, so'ng dasturchi yoki DBA dan so'rang.

Bu hisobotingizni qanday o'zgartiradi

✗ SQL siz

«Buyurtma yaratdim, lekin buyurtmalar ro'yxatida ko'rinmayapti.»

Dasturchi: «Menda ko'rinyapti. Cache tozalab ko'ring.»

✓ SQL bilan

«Buyurtma yaratdim. orders jadvalida qator bor (id = 8412), lekin user_id maydoni NULL — shuning uchun ro'yxat filtrida topilmayapti.»

Dasturchi: sababni darhol ko'radi.

Tekshirib ko'ramiz

1. Telefon raqami kiritilmagan foydalanuvchilarni topmoqchisiz. Qaysi so'rov to'g'ri?

2. Bir xil email bilan ikkita hisob ochilib qolganini qanday tekshirasiz?

3. Umumiy test bazasida ishlayapsiz. Qaysi buyruqni hech qachon o'zboshimchalik bilan ishlatmaysiz?

Eslab ko'ring — 10-darsdan: funksional va nofunksional test orasidagi farq nima? Nofunksional testni qachon boshlash kerak?

Funksional — tizim nima qilishini baholaydi («ishlaydimi?»). Nofunksional — qanchalik yaxshi qilishini (tezlik, qulaylik, xavfsizlik, moslik, ishonchlilik). Uni iloji boricha erta va barcha darajalarda boshlash kerak: kech topilgan nofunksional xato juda qimmatga tushadi.

Amaliyot: ikki qismli

A qism — SQLBolt (60–90 daqiqa)

sqlbolt.com — brauzerda ishlaydigan interaktiv mashq. Ro'yxatdan o'tish, o'rnatish kerak emas: so'rov yozasiz, sayt darhol to'g'ri-noto'g'rini aytadi.

  1. 1–6-darslarni bajaring. Bu SELECT, WHERE, ORDER BY, LIMIT va JOIN ni qamraydi — testerga kerakli asos.
  2. Har bir mashqda avval o'zingiz yozing, javobga qaramang. Xato qilish — o'rganishning bir qismi.
  3. Vaqtingiz bo'lsa 7–12-darslarni ham davom ettiring (COUNT, GROUP BY, NULL).

B qism — o'z so'rovlaringizni yozing (30 daqiqa)

Tasavvur qiling: ro'yxatdan o'tish formasini test qilyapsiz. Baza shunday tuzilgan:

users(id, email, full_name, phone, created_at, is_active)

Quyidagi holatlarni tekshirish uchun so'rov yozing:

  1. Yangi yaratgan foydalanuvchingiz haqiqatan saqlanganini tekshirish
  2. Bir xil email bilan ikkita hisob bor-yo'qligini tekshirish
  3. Ismi bo'sh yoki NULL qolgan hisoblarni topish
  4. Ismi bo'sh joy bilan boshlanadigan yoki tugaydigan hisoblarni topish (LIKE yordamida)
  5. Bugun yaratilgan hisoblarni sanash
  6. Faol bo'lmagan (is_active = false) hisoblarni eng yangisidan boshlab ko'rsatish

So'rovlarni yozib menga yuboring — men sintaksisni va, muhimrog'i, siz nimani tekshirmoqchi bo'lganingizni tekshiraman.

Maqsad — dasturchi bo'lish emas

Sizga murakkab so'rovlar yozish kerak emas. Kerak bo'ladigan narsa: SELECT … FROM … WHERE …, oddiy JOIN, COUNT va IS NULL. Shu to'plam bilan siz vakansiyalardagi «SQL asoslari» talabini qoplaysiz va hisobotlaringizga dalil qo'sha olasiz.

O'qish uchun (birlamchi manba)

PostgreSQL Documentation — Querying a Table SELECT, WHERE, ORDER BY va DISTINCT ning rasmiy tushuntirishi. Qisqa va aniq. Ingliz tilida.

Mashq uchun: SQLBolt — interaktiv darslar, brauzerda ishlaydi, bepul.

B qismdagi so'rovlarni yuboring. Sintaksis xatosi bo'lsa tuzataman; lekin men ko'proq qaraydigan narsa — qaysi tekshiruvni o'ylab topdingiz. Bazani ko'ra bilish odati shu yerdan boshlanadi.
