Hisobot qayerda yashaydi: Jira

1-darsda bug report yozdingiz, 4-darsda uning hayot siklini ko'rdingiz. Endi ikkalasi ham amalda qayerda sodir bo'lishini o'rganamiz. Bu darsdan keyin ish e'lonlaridagi «Jira bilan tajriba» talabi sizga tegishli bo'ladi.

Nega alohida tizim kerak

Xatoni Telegram'ga yozsangiz ham dasturchi ko'radi. Lekin bir oydan keyin quyidagi savollarga javob bera olmaysiz:

  • O'sha xato tuzatildimi? Kim tuzatdi? Qaysi versiyada?
  • Bu hafta nechta xato topildi, nechtasi ochiq qoldi?
  • To'lov bilan bog'liq xatolar qaysilar?
  • Bu xato oldin ham bo'lganmi?

Bug tracker (xato kuzatuv tizimi) — shu savollarga javob beradigan tizim. Eng ko'p tarqalgani — Jira. Prinsiplar esa hamma trackerlarda bir xil: Azure DevOps, YouTrack, Redmine, GitHub Issues — nomlar boshqa, mantiq o'sha.

Asosiy tushuncha: issue

Jira'da har bir ish birligi — issue (yoki yangi terminologiyada work item). Bu bitta karta: bitta vazifa, bitta xato yoki bitta story. Uning o'z raqami (SWAG-42), o'z egasi va o'z holati bo'ladi.

Maydonlar: hisobotingiz qayerga yoziladi

Yaxshi xabar: siz bularni allaqachon bilasiz. Jira maydonlari — 1-darsdagi bug report qismlarining aynan o'zi, faqat forma ko'rinishida.

Eng ko'p qilinadigan xato

Yangi testerlar hamma narsani Summary ga tiqishga harakat qiladi: «Savatda mahsulot sonini 0 ga o'zgartirsam sahifa oq bo'lib qoladi Chrome 120 da lekin Firefox da ishlaydi». Summary — bitta qisqa gap. Qolgani Description va Environment maydonlariga.

Status va Resolution — bu ikki xil narsa

Bu joyda deyarli hamma adashadi, shuning uchun sekin o'qing.

Status ish elementining workflow ichida qayerda turganini bildiradi. Atlassian — Introduction to Jira Workflows
Vazifa tugatilgach va endi ochiq bo'lmaganda, unga resolution qo'yiladi. Atlassian — Introduction to Jira Workflows

Status — qayerda

To Do · In Progress · In Review · In Test · Done

Ish jarayonining qaysi bosqichida turibdi.

Resolution — qanday tugadi

Done · Won't do · Duplicate · Cannot Reproduce

Yopilganda nima natija bilan yopildi.

Bir xil status ikki xil resolution bilan tugashi mumkin. Closed + Done — xato tuzatildi. Closed + Duplicate — xato tuzatilmadi, u boshqa issue'ning nusxasi edi. Ikkalasi ham «yopiq», lekin ma'nosi butunlay boshqa.

4-dars bilan bog'liqlik

4-darsdagi bug hayot sikli statuslari — Rejected, Duplicate, Cannot Reproduce, Deferred — Jira'da ko'pincha status emas, resolution sifatida yoziladi. Ya'ni issue Done statusiga o'tadi, lekin resolution Won't do bo'ladi. Hisobotingiz shunday yopilsa — 4-darsdagi javoblar amal qiladi: rad etilishini muhokama qiling, dalil qo'shing.

Manba: Atlassian — What are work item statuses, priorities, and resolutions?

Diqqat: Jira'da «Severity» yo'q

1-darsda severity (jiddiylik) va priority (navbat) farqini o'rgandik. Jira'ning standart sozlamasida faqat Priority maydoni bor — severity alohida maydon sifatida admin tomonidan qo'shiladi. Ba'zi jamoalarda u bor, ba'zilarida yo'q. Ishga kirganingizda birinchi kunlarda so'rang: «Bu yerda severity qayerda yoziladi?»

Issue'larni bog'lash — testerning kuchli quroli

Har bir bug ni Link orqali o'zi tegishli story'ga bog'lang. Bu bir necha narsani beradi:

  • Dasturchi story'ni ochib, unga tegishli hamma xatoni ko'radi.
  • Story «tayyor» deyilishidan oldin ochiq buglar borligi ko'rinib turadi.
  • Bir necha oydan keyin «bu qism qanchalik muammoli edi?» degan savolga javob bo'ladi.

Ko'p ishlatiladigan bog'lanish turlari: relates to (aloqador), blocks / is blocked by (to'sadi / to'silgan), duplicates (nusxasi), is caused by (sababi).

JQL — kerakli issue'ni topish

Loyihada minglab issue bo'lganda ro'yxatni varaqlab o'tirmaysiz. Jira'da JQL (Jira Query Language) degan qidiruv tili bor. Uch misol sizga ishning 90 % ini qoplaydi:

Mening ochiq hisobotlarim
reporter = currentUser() AND statusCategory != Done
Retest kutayotganlar
project = SWAG AND status = "In Test" ORDER BY updated DESC
Savat bilan bog'liq buglar
type = Bug AND labels = checkout

To'liq qo'llanma: Atlassian — Advanced search with JQL. Hozircha yodlash shart emas — shunday imkoniyat borligini bilib qo'ying.

Tekshirib ko'ramiz

1. Issue Closed statusida, resolution esa Duplicate. Bu nimani anglatadi?

2. Xatoni topdingiz. Uni Jira'da qaysi tur bilan yaratasiz?

3. «Chrome 120, Windows 11, sayt versiyasi 2.4.1» — bu ma'lumot qaysi maydonga yoziladi?

Eslab ko'ring — 7-darsdan: acceptance criteria'ning uch qismi qanday nomlanadi va ular test case'ning qaysi qismlariga to'g'ri keladi?

Given — dastlabki shart, When — qadamlar, Then — kutilgan natija. Shuning uchun yaxshi yozilgan acceptance criteria to'g'ridan-to'g'ri test case'ga aylanadi.

Amaliyot: o'zingizning Jira loyihangiz

Jira Cloud'ning bepul rejasi bor (10 foydalanuvchigacha). Portfolio uchun ham foydali: ish suhbatida «Jira bilan ishlaganman» deyish o'rniga ekranni ko'rsatasiz.

  1. Ro'yxatdan o'ting — atlassian.com/software/jira/free. Bepul reja, karta talab qilinmaydi.
  2. Loyiha yarating. Nomi: Swag Labs Testing, kalit: SWAG. Shablon: Scrum yoki Kanban — hozir farqi yo'q.
  3. Bitta Story yarating — 7-darsdagi saqlangan manzillar story'sini o'sha yerga ko'chiring. Description ga o'zingiz yozgan acceptance criteria'ni qo'ying.
  4. saucedemo.com da 30 daqiqalik sessiya o'tkazing (5-dars bo'yicha, DevTools ochiq holda — 6-dars).
  5. Uchta Bug yarating. Har birida: Summary bitta gap, Description da qadamlar + kutilgan + haqiqiy natija, Environment, Priority, kamida bitta skrinshot.
  6. Bog'lang va harakatlantiring. Bitta bug ni Story'ga relates to bilan bog'lang. Keyin barcha uchtasini To Do → In Progress → Done orqali o'tkazing — o'zingizni dasturchi o'rniga qo'yib ko'ring.
  7. Menga yuboring: uchta bug'ning matni (skrinshot yoki ko'chirib yozilgan holda). Men ularni dasturchi ko'zi bilan o'qib, qaysi biri qaytarib yuborilishini aytaman.

Bu — portfolioyingizning birinchi qismi

Tajribasiz nomzodning eng katta muammosi — ko'rsatadigan narsa yo'qligi. Shu loyihada 15–20 ta sifatli bug to'plansa, sizda ko'rsatiladigan ish bor. Har bir sessiyadan keyin shu loyihaga qaytib, yangi xatolarni qo'shib boring.
