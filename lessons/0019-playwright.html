Birinchi avtomatlashtirilgan testingiz

14-darsda nimani avtomatlashtirish kerakligini hal qildik. Endi kod yozamiz. Bu darsdagi hamma kod haqiqiy saytda ishga tushirilib tekshirilgan.

Nima kerak

Faqat Node.js (18-versiya yoki undan yangi). Boshqa hech narsa: Playwright brauzerni o'zi yuklab oladi.

# 1. Papka yarating va ichiga kiring
mkdir qa-avtomat && cd qa-avtomat

# 2. Loyihani boshlang
npm init -y

# 3. Playwright ni o'rnating
npm i -D @playwright/test

# 4. Brauzerni yuklab oling
npx playwright install chromium

To'rtinchi buyruq ~115 MB yuklaydi — bir marta, keyin kerak bo'lmaydi.

Birinchi test

tests/kirish.spec.js fayl yarating:

import { test, expect } from '@playwright/test';

test('to\'g\'ri hisob bilan kirish mumkin', async ({ page }) => {
  await page.goto('https://www.saucedemo.com/');
  await page.getByPlaceholder('Username').fill('standard_user');
  await page.getByPlaceholder('Password').fill('secret_sauce');
  await page.getByRole('button', { name: 'Login' }).click();
  await expect(page.getByText('Products')).toBeVisible();
});

Ishga tushiring:

npx playwright test

Har bir qatorda nima bo'lyapti

QismMa'nosi
test('nom', async ...) Bitta test. Nomi — 3-darsdagi test case sarlavhasi
{ page } Toza brauzer sahifasi. Har bir test o'z sahifasini oladi
await «Tugashini kut». Brauzerdagi har bir amal vaqt oladi
page.goto(...) Manzilga o'tish
getByPlaceholder(...) Elementni topish — lokator
.fill(...) / .click() Harakat
expect(...).toBeVisible() Tekshiruv — kutilgan natija

Tuzilma tanishmi?

goto → dastlabki shart. fill va click → qadamlar. expect → kutilgan natija. Bu 3-darsdagi test casening aynan o'zi, faqat kod shaklida. Shuning uchun yaxshi test case yoza oladigan odam uchun avtomatlashtirish — tarjima ishi.

Eng ko'p qilinadigan xato: await ni unutish

await siz kod «bosishni buyurdim» deydi va darhol keyingi qatorga o'tadi — bosish tugashini kutmaydi. Natija: goh o'tadigan, goh yiqiladigan test. Ya'ni 14-darsdagi flaky test, o'z qo'lingiz bilan yaratilgan.

Qoida: page. yoki expect( bilan boshlanadigan deyarli har bir qator oldida await turadi.

Lokatorlar — eng muhim qism

Test kodining sifati asosan lokator tanlashga bog'liq. Playwright tavsiya qiladigan tartib:

№LokatorNima bo'yicha topadi
1getByRole Element roli va nomi: tugma, havola, sarlavha
2getByText Matn mazmuni
3getByLabel Forma maydonining yorlig'i
4getByPlaceholder Maydondagi ko'rsatma matni
5getByAltText Rasmning matn muqobili
6getByTitle title atributi
7getByTestId Maxsus data-testid atributi
Rol lokatorlari foydalanuvchilar va yordamchi texnologiyalar sahifani qanday idrok etishini aks ettiradi. Playwright Docs — Locators

17-dars bilan bog'liqlik

getByRole aynan accessibility ma'lumotiga tayanadi. Demak: agar sahifa accessibility talablariga rioya qilsa, uni avtomatlashtirish osonroq bo'ladi. Va aksincha — lokator yozib bo'lmayotgan joy odatda ekran o'quvchi uchun ham ishlamaydigan joy.

✗ Nimadan qochish kerak

page.locator('.btn_primary.btn_inventory')

Bunday CSS lokator dizayner sinf nomini o'zgartirishi bilan sinadi — garchi sahifa foydalanuvchi uchun bir xil ishlayotgan bo'lsa ham. Bu 14-darsda aytilgan «qo'llab-quvvatlash xarajati» ning asosiy manbai.

Haqiqiy holat: bitta nomdagi oltita tugma

Shu darsni tayyorlaganimda quyidagi kodni yozdim va u ishlamadi:

// ✗ Ishlamaydi
await page.getByRole('button', { name: 'Add to cart Sauce Labs Backpack' }).click();

Sabab: saucedemo sahifasidagi oltita tugmaning ham nomi bir xil — shunchaki «Add to cart». Mahsulot nomi tugmada emas, uning yonidagi blokda.

Bu yerda Playwright ning muhim qoidasi ishlaydi: agar lokatorga bir nechta element mos kelsa, u xato beradi va tasodifiy birini tanlamaydi. Bu — yaxshi xususiyat: noaniqlik yashirin qolmaydi.

To'g'ri yechim — doirani toraytirish:

// ✓ Ishlaydi
const mahsulot = page.locator('.inventory_item')
  .filter({ hasText: 'Sauce Labs Backpack' });
await mahsulot.getByRole('button', { name: 'Add to cart' }).click();
await expect(page.locator('.shopping_cart_badge')).toHaveText('1');

Ya'ni: avval kerakli mahsulot blokini toping, so'ng uning ichidagi tugmani bosing. Bu eng ko'p ishlatiladigan naqsh — ro'yxatlar, jadvallar va kartochkalar bilan ishlaganda har doim shunday qilasiz.

Takrorni olib tashlash: beforeEach

Har bir test tizimga kirishdan boshlanadi. Uni ko'chirib yozmang:

import { test, expect } from '@playwright/test';

test.beforeEach(async ({ page }) => {
  await page.goto('https://www.saucedemo.com/');
  await page.getByPlaceholder('Username').fill('standard_user');
  await page.getByPlaceholder('Password').fill('secret_sauce');
  await page.getByRole('button', { name: 'Login' }).click();
});

test('savatga mahsulot qo\'shiladi', async ({ page }) => {
  const mahsulot = page.locator('.inventory_item')
    .filter({ hasText: 'Sauce Labs Backpack' });
  await mahsulot.getByRole('button', { name: 'Add to cart' }).click();
  await expect(page.locator('.shopping_cart_badge')).toHaveText('1');
});

beforeEach har bir testdan oldin bajariladi. Bu 3-darsdagi «dastlabki shart»ning kod ko'rinishi.

sleep ishlatmang

Yangi boshlovchilar «sahifa yuklansin» deb 3 soniya kutish qo'shadi. Bu ikki tomonlama yomon: sekin internetda 3 soniya yetmaydi (test yiqiladi), tez internetda esa bekorga kutiladi (test sekin).

Playwright element paydo bo'lishini o'zi kutadi. expect ham shart bajarilguncha qayta urinadi. Qo'lda kutish qo'shish — flaky testning ikkinchi eng ko'p sababi.

codegen haqida ogohlantirish

Bu — 14-darsdagi «record & playback» yondashuvi. O'rganish uchun ajoyib: lokator qanday yozilishini ko'rsatadi. Lekin uning chiqargan kodini o'zgartirmasdan ishlatmang — u ko'pincha mo'rt CSS lokatorlarni tanlaydi. Ishlatish tartibi: codegen bilan qoralama oling, so'ng lokatorlarni yuqoridagi jadval bo'yicha qayta yozing.

Yaxshi test kodining qoidalari

  • Bitta test — bitta tekshiruv (3-dars qoidasi o'sha-o'sha)
  • Testlar bir-biriga bog'liq emas: istalgan tartibda ishlashi kerak
  • Test nomi nimani tekshirayotganini aytadi
  • Lokatorlar foydalanuvchi ko'radigan narsaga tayanadi
  • Kutish qo'lda qo'shilmagan
  • Test o'zi yaratgan ma'lumotni o'zi tozalaydi (yoki har safar yangisini yaratadi)
  • Yiqilganda xato xabari sababni tushuntiradi

Tekshirib ko'ramiz

1. Lokatorga bir nechta element mos kelsa, Playwright nima qiladi?

2. Nega page.locator('.btn_primary') o'rniga getByRole('button', …) afzal?

3. Test goh o'tadi, goh yiqiladi. Birinchi navbatda nimani tekshirasiz?

Eslab ko'ring — 18-darsdan: nega performance o'lchovida o'rtacha emas, protsentil ishlatiladi?

Chunki o'rtacha eng yomon holatlarni yashiradi. 75 tasida 1 soniya, 25 tasida 12 soniya bo'lsa, o'rtacha 3.7 soniya chiqadi va hammasi yaxshi ko'rinadi — aslida har to'rtinchi foydalanuvchi azob chekyapti. Standart o'lchov — 75-protsentil.

Amaliyot

A — Loyihani qurib, uchta testni ishga tushiring (40 daqiqa)

  1. Yuqoridagi to'rt buyruq bilan loyiha yarating.
  2. Ikkita testni (kirish va savat) ko'chirib yozing va npx playwright test bilan yurgizing.
  3. --headed bilan qayta yurgizing — brauzerda nima bo'layotganini ko'ring.
  4. --ui rejimini ochib, qadamlar bo'ylab yuring.
  5. Ataylab sindiring: lokatordagi matnni o'zgartiring va xato xabarini o'qing. Playwright nimani kutganini aniq aytadi — bu keyinchalik juda ko'p vaqt tejaydi.

B — Uchta test o'zingiz yozing (40 daqiqa)

  1. Noto'g'ri parol bilan kirishga urinish → xato xabari ko'rinishini tekshirish.
  2. Ikkita mahsulot qo'shish → savat hisoblagichi 2 bo'lishini tekshirish.
  3. Savatdan mahsulotni olib tashlash → hisoblagich yo'qolishini tekshirish.

C — Test case'ni kodga aylantiring (30 daqiqa)

3-darsda yozgan test case'laringizdan ikkitasini tanlang va ularni Playwright testiga aylantiring. Dastlabki shart → beforeEach, qadamlar → harakatlar, kutilgan natija → expect.

C qismi nima uchun eng muhim

Bu mashq bitta narsani ko'rsatadi: test case aniq yozilgan bo'lsa, uni kodga aylantirish oson. Noaniq yozilgan bo'lsa («savat to'g'ri ishlashi kerak») — kod yozib bo'lmaydi.

Shuning uchun avtomatlashtirishdagi asosiy qiyinchilik kod emas. Kod — oxirgi, eng oson qadam. Asosiy ish undan oldin bajarilgan bo'ladi.

O'qish uchun (birlamchi manba)

Playwright Docs — Writing tests Rasmiy qo'llanma: birinchi test, harakatlar, tekshiruvlar. Ingliz tilida, qisqa va misollarga boy.

Lokatorlar bo'yicha: Playwright Docs — Locators. Bu sahifani bir necha marta qaytib o'qiysiz.

Yozgan testlaringizni yuboring. Men lokatorlaringizga qarayman — bu kod sifatining asosiy ko'rsatkichi. Va C qismidagi natijani ayting: qaysi test case'ni kodga aylantirish qiyin bo'ldi? Odatda javob shuki, o'sha test case yetarlicha aniq yozilmagan ekan.
