Ekranning orqasini ko'rish: DevTools

Shu paytgacha faqat ekranga qaradingiz. Endi brauzerning ichiga qaraymiz. Bu bitta ko'nikma sizning bug reportlaringizni ikki barobar qimmatliroq qiladi — va ish suhbatida boshqa nomzodlardan ajratadi.

Nega tester DevTools ni bilishi kerak

Ikki xil hisobotni taqqoslang:

✗ Faqat ekranga qaragan tester

«Saqlash tugmasini bosdim, hech narsa bo'lmadi.»

Dasturchi: «Menda ishlayapti.» → Cannot Reproduce.

✓ DevTools ni ochgan tester

«Saqlash tugmasini bosdim, hech narsa bo'lmadi. Konsolda: TypeError: Cannot read property 'id' of undefined. Network: POST /api/orders → 500.»

Dasturchi: darhol kerakli faylni ochadi.

Ikkinchi hisobot bir necha soatni tejaydi. Va u o'n soniya ko'proq vaqt oldi.

Bu darsning yagona maqsadi

Har bir bug reportga ikkita yangi dalil qo'shishni odat qilish: konsoldagi xato va muvaffaqiyatsiz tarmoq so'rovi. Boshqa hech narsa shart emas.

Manba: Chrome for Developers — Open Chrome DevTools va Keyboard shortcuts. Firefox va Edge da ham deyarli bir xil.

Console — dastur nimadan shikoyat qilyapti

Console — sahifadagi JavaScript kodining xato xabarlari joyi. Qizil qatorlar sizning eng qimmatli dalilingiz.

RangMa'nosiSizga kerakmi
Qizil — Error Kod ishlayotganda uzilib qoldi Ha — doim hisobotga qo'shing
Sariq — Warning Ogohlantirish, lekin ish davom etdi Ba'zan — xato bilan bir vaqtda chiqsa
Oq/kulrang — Log Dasturchining o'z eslatmalari Odatda yo'q

Ish tartibi

Xatoni takrorlashdan oldin Console ni tozalang (🚫 belgisi yoki Ctrl+L). Shunda qaysi xato aynan sizning harakatingizdan chiqqani aniq bo'ladi. Aks holda sahifa yuklanishidagi eski xabarlar aralashib ketadi.

Network — server nima javob qaytardi

Network paneli sahifa serverga yuborgan har bir so'rovni ko'rsatadi. Sizga faqat bitta ustun kerak: Status.

KodMa'nosiKim aybdor
2xx (200, 201) Muvaffaqiyatli —
3xx (301, 302) Boshqa manzilga yo'naltirildi Odatda normal
4xx (400, 401, 403, 404) So'rovda muammo: noto'g'ri ma'lumot, ruxsat yo'q, topilmadi Ko'pincha frontend yoki ruxsatlar
5xx (500, 502, 503) Server ichida xato yuz berdi Backend — deyarli har doim haqiqiy bug

Amaliy qoida: qizil qator ko'rsangiz — bu topilma. So'rovni bosing, Headers da manzilni va Response da server javobini ko'ring. Ikkalasini hisobotga qo'shing.

Uchta sozlama — bir marta yoqib qo'ying

  • Preserve log — sahifa yangilanganda yozuvlar o'chmasin. Yo'naltirishlarni kuzatish uchun zarur.
  • Disable cache — DevTools ochiq bo'lganda eski nusxa ishlatilmasin.
  • Fetch/XHR filtri — rasm va stillarni yashirib, faqat ma'lumot so'rovlarini ko'rsatadi.

Yana ikkita foydali narsa

Telefon rejimi

DevTools tepasidagi telefon belgisi (Ctrl+Shift+M) sahifani turli ekran o'lchamlarida ko'rsatadi. Mobil versiyani sinash uchun eng tez yo'l. Diqqat: bu haqiqiy telefon o'rnini bosmaydi, lekin layout xatolarini topishga yetadi.

Elements — HTML ni ko'rish

Ctrl+Shift+C bosib, istalgan elementni bosing. Tester uchun eng foydali ishlatilishi: maydonchaning haqiqiy chegarasini tekshirish. Masalan HTML da maxlength="10" yozilgan bo'lsa, siz 11-belgini kirita olmaysiz — chunki brauzer to'sib qo'yadi, server emas. Bu ikki xil holat va hisobotda farqlanadi.

Tekshirib ko'ramiz

1. Network panelida 500 statusi ko'rindi. Bu nimani anglatadi?

2. Nega xatoni takrorlashdan oldin Console tozalanadi?

3. Maydoncha 10 belgidan ortiq qabul qilmayapti. HTML da maxlength="10" yozilgan. Xulosangiz?

Eslab ko'ring — 5-darsdan: exploratory sessiyaning uchta ustuni nima?

Charter (sessiyaning maqsadi, 1–3 gap), timebox (30–45 daqiqa, taymer bilan) va yozuvlar (sessiya davomida: BUG / SAVOL / G'OYA).

Amaliyot: dalilli hisobot

  1. saucedemo.com ni oching va F12 bosing. Network panelini oching, Fetch/XHR filtrini va Preserve log ni yoqing.
  2. standard_user bilan kiring. Login bosilganda Network da qanday so'rov ketdi? Statusi nechchi?
  3. Chiqing va noto'g'ri parol bilan kiring. Endi status qanday? Server javobida (Response) nima yozilgan?
  4. Console ni tozalang va problem_user bilan kirib, saytni aylanib chiqing. Qizil xatolar chiqdimi? Chiqsa — matnini to'liq nusxalang.
  5. Ctrl+Shift+M bosib telefon rejimini yoqing. Mahsulot ro'yxati va checkout formasi buzilmaydimi?
  6. Topgan bitta xatoni to'liq hisobot qilib yozing — endi «Dalil» qismida skrinshotdan tashqari konsol xatosi va tarmoq so'rovi statusi ham bo'lsin.
  7. Menga yuboring.

Bu yerda nima o'zgardi

Oldin siz «nima ko'rindi» ni yozardingiz. Endi «tizim ichida nima sodir bo'ldi» ni ham yoza olasiz. Ish e'lonlarida «DevTools bilan ishlash ko'nikmasi» deb yozilgan talab aynan shu — murakkab narsa emas, lekin ko'p boshlovchilar buni o'tkazib yuboradi.

O'qish uchun (birlamchi manba)

Chrome for Developers — Inspect network activity Google ning rasmiy qo'llanmasi. Amaliy mashq shaklida yozilgan — o'qib emas, bajarib o'rganiladi.

Tushunmagan xato xabari bo'lsa — menga tashlang. Konsoldagi matnni nusxalab yuboring, men uni sodda tilda tushuntiraman va bu qanday bugga ishora qilishini aytaman. Bu — texnik tilni o'rganishning eng tez yo'li.
